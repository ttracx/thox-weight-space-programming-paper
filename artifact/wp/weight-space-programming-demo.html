Weight-Space Programming, hands on

Four small instruments from the whitepaper, running on its measured data. Every number is labelled with its evidence class and comes from the result files in the paper's artifact bundle.

1. Read: find the task in the composed maps

Below are the per-class effective input-to-logit maps (E = W2TW1T) of one trained 64-48-4 network from experiment E1. Its task was one of: name the dot's column, its row, or its diagonal class on an 8x8 grid. Three of the paper's four readers scored at chance on maps like these; the per-class composed reader (R4) scored 100% over 30 networks. Pick a network, look at the four class maps, and guess before you reveal.

The class maps are |E| intensities (green = strong). A column task concentrates each class map in one column band; a row task in one row band; a diagonal task along diagonals.

2. Fix: sixteen weights, one dose-response

Experiment E3 repaired a MountainCar policy stuck at 0% success by editing 16 of 747 weights (2.14%): two velocity detectors, an energy-pumping override pathway, output gain. A random edit of the same size scored 0%. Drag the override gain and watch success respond; 1.0 is the shipped edit (92.8% over 512 episodes; the curve below is the 256-episode sweep).

4. Ship: size a signed rank-1 patch

The patch channel ships an edit as factors (direction u, column set, alpha), signed in a manifest that pins the base model's tensor hashes. Defaults below are the Experiment 8 tensor. Change the geometry and compare representations.

Lifecycle enforced by the Rust loader: verify Ed25519 signature, verify base hashes, apply to the inactive A/B slot, verify result hashes, switch atomically, roll back in one command. End-to-end test (Python signer, Rust loader): all checks pass, including tamper rejection and wrong-base abort. Calculated sizes.

5. The control: loop baseline

The scoped loop baseline was still running on the THOX build VM when this demo edition was built. Its results table is inserted in the next edition; the paper's Section 5 carries the status. Nothing in this demo depends on it.
